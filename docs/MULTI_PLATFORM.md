# 多渠道接入指南（Multi-Platform Integration）

> 目标：把「Enterprise AI Knowledge Assistant」接入企业员工实际使用的入口——飞书、企业微信、钉钉、Web 嵌入与业务系统 API，让知识助手"长在员工每天打开的 IM 里"。
> 前提：已完成基础部署与知识库导入（见 [DEPLOYMENT.md](DEPLOYMENT.md)），应用已发布。
> 说明：本文档为实施指引，步骤以各平台官方文档与 Dify 官方插件页为准；渠道接入不改动应用工作流，回答的**引用来源 / 兜底转人工**逻辑在所有渠道保持一致。

---

## 1. 为什么需要多渠道（业务价值）

| 场景 | 渠道 | 收益 |
| --- | --- | --- |
| 员工日常答疑 | 企业微信 / 飞书群聊 @ 机器人 | 高频问题在 IM 内直接解决，不切系统 |
| 售后 / 客服坐席 | Web App 嵌入工单系统 / 客服台 | 坐席边接待边检索，回答带引用可审计 |
| 外部客户自助 | Web App 分享链接 / 嵌入官网 | 7×24 自助问答，降低人工咨询量 |
| 系统联动 | Service API 对接 OA / 工单 / 呼叫中心 | 知识查询成为业务流程的一环 |

## 2. Dify 多渠道能力总览（2026-10 核实）

Dify 应用「发布」后提供三类出口，且官方插件市场（Marketplace）提供 IM 渠道插件：

| 出口 | 方式 | 说明 |
| --- | --- | --- |
| Web App | 发布后生成分享链接 / 可嵌入 iframe | 零配置，最快落地；分享页渲染引用卡片 |
| Service API | 发布时生成 API（chat-messages 等） | 供自建系统调用，官方 SDK 多语言 |
| IM 机器人 | 官方渠道插件 / 开源桥接 | 见下表 |

**官方插件市场渠道插件（langgenius 出品，安装量截至 2026-10）**：

| 渠道 | 插件 | 安装量 | 接入方式要点 |
| --- | --- | --- | --- |
| 企业微信群机器人 | `langgenius/wecom` | 161,717 | 群工具添加群机器人获取 Webhook Key；机器人把群消息作为输入发回群 |
| 钉钉 | `langgenius/dingtalk` | 156,130 | 钉钉开放平台创建机器人 / 企业应用，配置回调 |
| Slack | `langgenius/slack-bot` | 官方扩展 | 创建 Slack App，链接到 Chatflow/Chatbot/Agent，生成 endpoint URL |
| Telegram | `langgenius/telegram_trigger` | 官方 Trigger 示例 | Bot API 注册 webhook（仅需 bot token） |
| 多 IM 统一入口 | `rockchinq/langbot_trigger` | 785 | 接收 QQ / WeChat / Telegram / Discord / Slack / LINE / Lark / DingTalk 消息（LangBot 生态） |

**开源桥接项目（不依赖插件市场，自部署）**：

| 项目 | 渠道 | 特点 |
| --- | --- | --- |
| dify-on-lark（Gitee） | 飞书 | 轻量级，群聊/私聊智能问答，支持飞书 AI 卡片流式打字机输出 |
| dify-on-dingtalk | 钉钉 | 开源框架，钉钉内打字机式流式输出 |

## 3. 方案 A：Web App 分享与嵌入（最快落地，零开发）

1. 控制台打开应用 → 点击「发布」→ 获取 Web App 链接（`/chat/xxx`）。
2. 分享给内部员工，或复制嵌入代码（iframe）贴入 OA / 客服台 / 官网。
3. 分享页天然支持：对话历史、引用卡片、建议问题。

> 适合：先跑通业务、验证回答质量后再上 IM 机器人。

## 4. 方案 B：Service API 对接业务系统

1. 「发布」→「API 访问」→ 生成 Service API 密钥（`app-` 开头）。
2. 调用 `POST /v1/chat-messages`，入参 `query` + `conversation_id`，流式返回回答与引用。
3. 官方 SDK：Python / JS / Go / Java 等（`sdks/`）。

> 适合：工单系统、OA 门户、呼叫中心坐席台内嵌"知识检索"能力。

## 5. 方案 C：企业微信群机器人（官方插件，国内员工最常用）

### 5.1 准备工作
- 已部署 Dify 实例；控制台 → 「插件」→ 安装 `langgenius/wecom`（需可访问插件市场；国内受限时见第 8 节）。
- 一个有权限的企业微信群。

### 5.2 配置步骤
1. 企业微信 → 目标群 → 右上角「群工具」→「添加群机器人」→ 命名机器人（如"云帆知识助手"）→ 复制 Webhook URL 中的 Key。
2. Dify 插件配置页：填入 Webhook Key，选择要关联的已发布应用（Enterprise AI Knowledge Assistant）。
3. 保存并启用；在群里 @ 机器人或直接发消息提问，机器人调用工作流并回传答案（含引用来源）。

### 5.3 验证
- 群内提问「VPN 连接超时怎么办」→ 收到基于知识库的回答与引用。
- 提问无关内容（如"今天天气"）→ 收到兜底转人工话术。

## 6. 方案 D：飞书机器人

### 6.1 路径 1：dify-on-lark 桥接（推荐，支持流式卡片）
1. 飞书开放平台创建**企业自建应用**，开启「机器人」能力；配置事件订阅（接收消息）。
2. 获取 App ID / App Secret / 长连接或回调地址。
3. 部署 [dify-on-lark](https://gitee.com/duhongming/dify-on-lark)（轻量服务），配置 Dify 应用地址与飞书凭证。
4. 发布应用到企业，员工在飞书群聊/私聊中直接问答，支持 AI 卡片流式输出。

### 6.2 路径 2：自定义机器人 Webhook（只发不收）
- 飞书群 → 设置 → 群机器人 → 添加自定义机器人 → 获取 Webhook。
- 结合 Dify Service API 或工作流 HTTP 节点可实现"关键词触发 → 把回答推回群"（单向通知场景）。

## 7. 方案 E：钉钉机器人

1. 钉钉开放平台创建企业内部应用 / 机器人，获取 AppKey、AppSecret（企业应用需要管理员审核或后台启用）。
2. 部署 [dify-on-dingtalk](https://github.com/zfanswer/dify-on-dingtalk)（开源框架，支持流式输出）。
3. 将机器人添加进群，@机器人提问即可，配合 Dify 标注功能可实现固定指令输出。

## 8. 国内部署注意事项（结合本项目的国产化方案）

| 注意点 | 处理 |
| --- | --- |
| 插件市场访问 | 官方插件市场域名 marketplace.dify.ai 国内可能受限；可配置网络代理安装插件，或改用第 6/7 节开源桥接方案（自部署，不依赖插件市场） |
| 回调地址 | IM 平台回调/事件订阅要求**公网可访问的 HTTPS 地址**；云服务器部署时配置域名 + 证书（如 Nginx/Caddy 反代 + Let's Encrypt，见 README_CN 第 7 节 FAQ） |
| IP 白名单 | 企业微信自建应用回调需配置可信 IP；如使用群机器人 Webhook 则无此要求 |
| 内网部署 | 若 Dify 部署在内网，IM 桥接服务需与 Dify 内网互通；飞书/企微云服务无法直达内网，需公网入口或反向代理 |
| 模型与知识库 | 渠道接入复用同一工作流：国产模型（DeepSeek/通义/智谱）、引用来源、兜底转人工均不受渠道影响（见 [CN_MODEL_PROVIDERS.md](CN_MODEL_PROVIDERS.md)） |

## 9. 落地优先级建议

| 阶段 | 动作 | 工作量 |
| --- | --- | --- |
| 第 1 步 | Web App 分享链接 / 嵌入（方案 A） | 10 分钟，零开发 |
| 第 2 步 | 企业微信群机器人（方案 C，官方插件） | 约 30 分钟 |
| 第 3 步 | 飞书机器人（方案 D，dify-on-lark） | 约 1-2 小时 |
| 第 4 步 | Service API 对接业务系统（方案 B） | 按业务系统工作量 |

## 10. 验证清单

- [ ] Web App 分享链接可访问，问答带引用卡片
- [ ] 企微群里 @ 机器人提问，返回结构化答案（含「引用：[文档名]」）
- [ ] 无关问题在 IM 渠道同样走兜底转人工
- [ ] 渠道回复与 Web App 回答口径一致（同一工作流）
- [ ] 国内环境：插件市场受限时已采用开源桥接方案
