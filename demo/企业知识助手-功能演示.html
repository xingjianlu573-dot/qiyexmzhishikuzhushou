    多渠道接入

    同一套工作流（知识库检索 + 引用来源 + 兜底转人工）可发布到员工日常使用的入口；接入方式基于 Dify 官方渠道插件与开源桥接方案，详见 docs/MULTI_PLATFORM.md。

    Web App / 嵌入
    最快落地 · 分享给员工或嵌入 OA/官网
    • 发布后生成分享链接，零配置
    • iframe 嵌入工单系统 / 客服台 / 官网
    • 分享页原生支持引用卡片与建议问题
    接入：应用「发布」→ Web App
    企业微信群机器人
    国内员工最常用 · 群内直接提问
    • Dify 官方插件 langgenius/wecom（16 万+ 安装）
    • 群工具添加机器人，填 Webhook Key 即接入
    • 群里 @ 机器人提问，回答回传群聊
    接入：Dify 插件市场安装 Wecom 插件
    飞书机器人
    群聊 / 私聊问答 · 流式 AI 卡片
    • 开源桥接 dify-on-lark（Gitee）轻量部署
    • 飞书自建应用开启「机器人」能力
    • 支持飞书 AI 卡片流式打字机输出
    接入：dify-on-lark 桥接 + 飞书开放平台
    钉钉机器人
    钉钉群 @ 问答 · 流式输出
    • 官方插件 langgenius/dingtalk（15 万+ 安装）
    • 或 dify-on-dingtalk 开源框架
    • 企业应用需管理员审核或后台启用
    接入：Dify 插件 / dify-on-dingtalk
    Service API
    对接业务系统 · 知识查询进业务流程
    • 发布生成 API 密钥（app- 开头）
    • POST /v1/chat-messages 流式返回回答与引用
    • 官方多语言 SDK（Python / JS / Go / Java）
    接入：应用「发布」→ API 访问
    国内部署要点
    多渠道在国内环境的落地前提
    • 插件市场受限时改走开源桥接（自部署）
    • IM 回调需公网 HTTPS 地址（Nginx/Caddy 反代 + 证书）
    • 企微自建应用需配置可信 IP 白名单
    详见 docs/MULTI_PLATFORM.md 第 8 节
